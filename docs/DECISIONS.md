# Implementation decisions

## Generator v5.1: coverage-guided range exploration

- Each moving hand keeps five coarse pitch-region counts in ephemeral `StreamState.coverage`. Actual generated noteheads, including chord tones and excluding rests, update a normalized per-phrase histogram with 0.95 decay (roughly a fourteen-phrase half-life). No settings, dependencies, database migration or persisted coverage are added.
- `src/generation/rangeCoverage.ts` selects underused regions with seeded weighted randomness, keeping every region eligible. A target is the nearest approved same-shape position center. It persists until reached or for a randomized 32–64 phrase planning horizon, allowing sparse Easy movement opportunities to accumulate progress. Blocked targets expire; configured ranges need not be covered within any one phrase or session.
- At the phrase boundary, a seeded 75% chance permits a one-index contour-register offset toward the target. The existing motif, harmony, cadence and note-level constraints still determine the melody. At existing rested relocation opportunities, legal candidates retain their small-move weights and receive bounded 0.1–1 acceptance weights according to progress toward the target. Unused weight defers the move, which matters when only the opposite direction has a legal landing. Neither movement frequency nor distance/interval/spacing/collision limits can increase. Movements Off, zero frequency and zero distance bypass coverage guidance entirely.
- Hands retain independent counts/targets through chunk continuation. New exercises start fresh. Generation-context changes reset coverage; assistance, tempo and presentation changes do not alter it. Structural settings still start a new exercise through the practice controller, preserving the existing hand-continuity contract.
- Generator version **5.1.0** separates the changed seeded content and comparisons from 5.0.0. The existing v5 session shape accepts both version tags; old backups keep their original fingerprints and are not offered current-version exact replay.
- Statistical tests compare 24 seeded 96-phrase sessions against an ablation restoring the previous sampler and RNG consumption, over C3–C5 and C3–C6. Additional tests cover bounded memory, target persistence/reset, short-phrase variety, movement reversals, difficulty limits and independently validated two-hand/chromatic/chord continuations. These model checks do not establish human comfort or hardware MIDI compatibility.

## Generator v5: independent hand ranges

- Active settings retain `min`/`max` as right-hand bounds and `leftMin`/`leftMax` as left-hand bounds, regardless of which hands are enabled. `rangeVersion: 2` identifies the independent interpretation. Switching hands or difficulty preserves both ranges. Both support A0–C8 (MIDI 21–108); a usable five-note position in the selected key is still required.
- Legacy left-only preferences used `min`/`max` for the active left hand. Migration copies those bounds into the left range and retains the shared values for the right hand. Legacy right/both preferences retain both stored ranges. Migration applies only to active preferences, once; historical settings and fingerprints are unchanged.
- The compact Edit range action opens a full-screen native dialog with an 88-key piano, horizontal scrolling, hand switches, endpoint controls, keyboard navigation and staged Apply/Cancel. Invalid narrow ranges receive feedback before Apply. Overlapping configured ranges are allowed when separate playable positions fit; generation and independent validation retain the existing collision rules.
- Positions, chromatic alternatives, chords and explicit rested relocations use the bound pair for their own hand, including in single-hand practice and continuous chunks. The range interpretation changes the generator version to **5.0.0**. V1–v4 history/backups retain their original schemas and comparison series; exact replay remains limited to the current generator.

## Generator v4: chromatic pitch plans and simultaneous events

These rules extend v3. The five independent controls are Note jumps, Hand movements, Finger spacing, Accidentals and Chords. The latter two default to Off when migrating active preferences. Ranges, rest preparation, movement caps, explicit landing cues and exact integer ticks remain authoritative.

- A score event has `notes`, an array of individually identified noteheads carrying MIDI, spelling, written letter/octave/accidental/key, finger and hand. The primary event fields mirror its first notehead for compatibility with existing callers. `noteheads()` also reads legacy single-note events. Rests have no noteheads. V4 seeds produce new material; v1/v2/v3 history keeps its original schema, fingerprint and outcomes, and exact replay remains version-specific.
- The position's diatonic map stays fixed. When accidentals are enabled it also carries explicit same-finger `pitchOptions`. These preserve the written letter and differ from the base pitch by one semitone; double accidentals and chromatic alternatives under fingers 1/5 are excluded initially. Each option must remain inside range, ordered anatomically, within the ten-semitone map envelope, and within existing adjacent-finger semitone limits. Horizontal white-key-center distance is capped at 2.5 key widths for thumb/index and index/middle, 1.5 for middle/ring and ring/little. The validator reconstructs options independently. This models black-key reach conservatively; it is not hand-size calibration or evidence of human comfort.
- Easy accidentals use occasional resolving neighbors (12% eligible attack probability); Medium uses more neighbors and harmonic passing tones (28%); Hard uses frequent figures (45%) and favors Tonal dominant-seventh color tones. Alterations resolve to a base pitch on the next sounded attack, except when an explicitly prepared move takes precedence. Pending resolution, final actual pitch, last voicing, RNG and hint memory carry across chunks. These percentages describe opportunities, not guaranteed density under every range and rhythm.
- Harmony uses Tonal major/minor triads over I–IV–V–I, I–ii–V–I or I–vi–IV–V. Chords add voices to the existing melodic anchor. Easy permits approved dyads at 22% of eligible opportunities and at most seven semitones; Medium permits dyads/triads at 45%, including inversions that fit the map; Hard permits 70% and selected four-tone sixth/minor-seventh voicings. Medium/Hard span is capped at nine semitones. Four-note chords often require an enabled spacing pattern; narrow ranges or spacing Off can legitimately prevent them.
- Approved finger combinations: dyads 13/14/15/24/25/35; triads 135/125/145/124/245; four-note shapes 1235/1245/1345. A chord must use distinct pitches and fingers, the active map/options, the selected harmony and approved interval content. Major/minor triads must contain the complete harmonic pitch-class set. Extra black-key outer-finger/white-key inner-finger combinations and excessive horizontal gaps are rejected. The independent validator rechecks all constraints rather than calling candidate helpers. Hard never overrides the limits.
- Melodic anchors retain the selected jump cap. Consecutive chords also check voice proximity in both directions against that cap; added/removed voices do not raise the melodic difficulty. A candidate that fails falls back to the already planned single note. Chromatic notes do not become movement events. Positions and spacing shapes remain consistent across bars and chunks.
- VexFlow engraves every notehead and attaches its own indexed `FretHandFinger` modifier at the right of a chord. Smart projects the validated mapping over each head using existing inference memory: a conventional 1/3/5 triad needs one establishing number; spacing exceptions and move landings keep their cues. All/Smart/None and Reveal never change notes or grading.
- Accidentals are tracked per staff, written letter and octave within each measure. Signature alterations establish the baseline; repeated signs are suppressed, naturals cancel, and barlines reset state. The accidental projection supports tied-continuation suppression without establishing state for a later untied attack. The current rhythm generator does not emit ties or cross-bar notes.
- MIDI grades the required pitch union at each onset, independently of finger assignments. Default simultaneous capture is **120 ms**, configurable through the scorer constructor. A sliding capture window allows retries after slow arpeggiation; expired captures cannot earn first-attempt chord credit. Note-level credit is recorded once, missing heads remain explicit in timed mode/skip, and chord-event accuracy requires every head in the capture with no wrong/extra input. Surplus attacks within the original capture window, even immediately after completion, invalidate chord credit and are attributed to that capture. Fresh attacks for a following valid target remain eligible.
- CC64 is normalized by WEBMIDI.js. Physical key depression is separate from pedal-held sound. Sustain never creates a note attack, and releasing/restriking a key with the pedal down can satisfy a repeated note. Both hands share the onset capture and cannot credit the same pitch twice; generated hand envelopes remain separated.
- V4 outcomes persist notehead IDs, event IDs/sizes and simultaneous success. UI/history/CSV report chord-event accuracy separately from note accuracy and wait throughput/timed accuracy. Fingerprints include both new controls; no sample results are introduced.

Remaining review: physical MIDI/pedal timing, comfortable black-key and chord shapes for different hands, musical phrasing, and browser/tablet engraving legibility. No general fingering optimizer, crossings, double accidentals, independent hand rhythms or universal ergonomic guarantee is claimed.

## Generator v3: independent difficulty and variable spacing

These v3 rules supersede the overall v2 presets below; v2 notes remain as historical documentation.

| Dimension | Levels and generation behavior |
|---|---|
| Note jumps | Small: at most one scale step; Easy: two; Medium: four; Large: seven. Extra weights for stepwise movement are respectively 7/4/2/0, on top of the existing harmonic/motif/contour weights. Advanced interval values may lower, never exceed, the selected cap. |
| Hand movements | Off: no opportunities, zero frequency/distance; Easy: bar 3, 25%, one-step default (two-step safety cap); Medium: bars 2/4, 55%, two-step default (three-step cap); Hard: bars 2/3/4, 85%, four-step default/cap. The one-full-beat rest, advance cue, novel landing, collision and independent melodic limit checks remain mandatory. |
| Finger spacing | Off: natural only. Easy: 30% variable-position selection, thumb gap. Medium: 60%, thumb or index gap. Hard: 85%, also two gaps. Sampled independently per hand at exercise initialization, conditional on compatible available positions. The same spacing shape is retained at every relocation. |

- The three button groups set only their own dimension and its corresponding advanced defaults. There is no active overall difficulty setting. Key, rhythm, meter, clefs, exact limits, MIDI and seed stay in Advanced settings. Note-name keyboard-range editors are collapsed initially. No range is overwritten by a difficulty or hand choice.
- Positions explicitly carry `fingerToMidi` indexed by finger minus one, plus correctly spelled ascending `pitches`. Library offsets in **finger order away from the thumb** are natural `[0,1,2,3,4]`, thumb gap `[0,2,3,4,5]`, index gap `[0,1,3,4,5]`, and two gaps `[0,2,4,5,6]`. LH patterns reflect their RH counterparts anatomically: the larger gaps stay near the thumb/index, not the ring/little fingers. RH C4/E4/F4/G4/A4 and LH A4/F4/E4/D4/C4 are examples of the thumb-gap shape.
- Safety limits: strictly ordered scale notes, total span at most ten semitones, adjacent thumb–index/index–middle distances at most four semitones, middle–ring/ring–little distances at most two. Only the enumerated shapes are accepted, with at most one omitted degree per allowed gap; arbitrary ordered pitches passing the span cap are still rejected. The independent validator reconstructs the library and limits without planner helpers. These are conservative software constraints, **not teacher-reviewed proof of comfort**; physical review is outstanding.
- A map never changes mid-position. Spacing is not a movement, and Off movements keeps that exact map across the entire continuous exercise. Movement candidates must preserve the shape and have a new anchor and a landing outside the old map. Larger jumps do not enable movements or spacing. Spacing does not increase the melodic interval cap.
- Predictable constraints/fallback: no conventional five-note position means an actionable error, never range widening. If no compatible approved variable position fits, choose conventional spacing. The range summary explains this (for both hands, compatible non-overlapping pairs are required). A relocation without a legal target within the range, current shape, separation and jump limit is omitted, keeping the exact previous position. With Small jumps, gaps can separate the map into reachable segments: the melody starts in one of the largest connected regions and stays in its current segment rather than exceeding the jump limit. Preparation rests remain reserved even if a move is omitted. Difficulty levels describe allowed opportunities, not a promise that every short phrase exercises every allowed interval or finger.
- Smart inference uses the **validated map**, not the distance from the preceding melody note. An annotated finger establishes its oriented scale coordinate minus finger index. Unannotated fingers follow adjacent scale degrees from the nearest established lower finger (or nearest higher finger if no lower anchor exists). An annotation is essential exactly when the planned assignment cannot follow that convention; its offset then propagates to later adjacent fingers. For C4/1 → E4/2 → F4/3 → G4/4 → A4/5, only 1 and 2 are needed. An index gap needs 1 and 3; two gaps need 1, 2 and 3, when played in finger order. Arbitrary first fingers/directions are supported by the same model. This is a declared default-inference convention, not a claim that an unmarked score mathematically identifies every possible human fingering.
- Each hand remembers its own active anchors and previously established maps. Every actual move still shows its landing finger; returning to a known map retains its spacing exceptions. First relevant exceptions appear beside the corresponding future notes as soon as those notes enter the visible score. VexFlow `FretHandFinger` remains the authoritative annotation. There is no manual request for an essential Smart cue.
- `StreamState.hints` carries pure inference memory with the retained final hand/RNG state. Notation projects over the retained full phrase buffer using its first chunk's initial memory, then displays the current window. Evicting earlier chunks, changing hint modes, revealing, or scrolling neither forgets exceptions nor duplicates initial cues. Memory is computed from the Smart plan independently of the visible assistance mode, so switches do not change notes, timing, cursor or fingering. All still annotates every note; None permits optional reveal outside benchmarks.
- Generator version is **3.0.0**. Fingerprints include all three levels, numerical overrides and assistance. V1/v2 imports retain their original schema/fingerprint and historical version; exact replay is enabled only for v3. Active legacy preferences migrate their interval/movement limits with spacing Off. No historical outcomes are relabelled as v3.

## Generator v2: positions and deliberate relocation

- The generator builds notes from explicit five-note diatonic `HandState` maps. RH fingers ascend 1–5; LH fingers descend 5–1. It is not a general-purpose fingering optimizer. MIDI cannot verify the human finger used.
- Tonal supplies spelling and chord tones. Each four-bar phrase selects a contour, a small recurring motif and an I–IV–V–I or I–ii–V–I harmonic outline. Chord tones receive extra weight; the final sounded event prefers a reachable tonic-chord tone. Hard constraints take priority over cadence preferences.
- Starting positions are sampled from **all valid positions inside the selected range**. Both-hand initialization samples compatible non-overlapping position pairs. Narrow C4–G4 naturally permits only one position; the UI explains this rather than forcing C4 in broader ranges. Presets and hand selection do not overwrite ranges.

| Preset | Eligible landing bars in each four-bar phrase | Chance per eligible opportunity, per hand | Default maximum shift | Default maximum melodic interval |
|---|---|---|---|---|
| Very Easy | None | 0% | 0 | Third |
| Easy | 3 | 25% | 1 scale step | Third |
| Medium | 2, 4 | 55% | 2 scale steps | Fifth |
| Hard | 2, 3, 4 | 85% | 4 scale steps | Octave |

- Advanced settings independently adjust probability, maximum repositioning distance and maximum melodic interval. Distance is the signed change of the **lowest note of the five-note position**, measured in diatonic scale steps; it is not the melodic leap. Advanced shift-distance safety caps are Easy 2, Medium 3 and Hard 4 steps. Very Easy rejects nonzero movement settings. A large interval can use two fingers in the same position without moving the hand.
- Only **lift-and-reposition after a full quarter-note rest** is implemented. Preparatory rests are reserved before eligible boundaries, even when the chance test or range constraints result in no shift. Actual relocations must land on a note unavailable in the old position; all landing choices obey the separate melodic interval limit. Smaller relocations receive greater weight, but larger allowed distances are genuinely generated.
- A movement stores source and destination position IDs, technique, cue tick, landing tick, note ID, pitch, finger and signed distance. The cue occurs at the start of the preparatory rest, one beat before the landing. The `positions` list, initial/final states and every score event preserve the complete fingering plan.
- Shifts are planned only inside a chunk, never silently at its first event. Final position, last sounded pitch, last note end tick and RNG state carry into the next chunk. Very Easy keeps the same position for the entire continuous stream. Both hands have independently validated positions/movements and are prevented from overlapping throughout the movement sequence.
- The independent validator reconstructs the active position for every event and rechecks spelling, range, finger map, interval, actions, exact measure lengths, resting preparation, advance cue, landing identity, movement limits, hand collisions and final state. It does not call planner candidate-selection helpers. Infeasible ranges fail with actionable errors; a feasible narrow range may legitimately yield no shifts, which is explained by the UI.

## Hints and comparisons

- Three UI modes: **All**, **Smart (default)** and **None**. Smart automatically supplies initial placement per hand, the first finger, every explicit shift landing, and any validated non-obvious assignment; ordinary position-consistent notes have no redundant numbers. None hides automatic guidance but retains an unobtrusive movement indicator and manual Reveal. Independent benchmark mode permits no reveal.
- `selectFingeringHints` is a deterministic, pure projection of the validated events, position maps and movement list. It exposes the position before/effective at each note, expected and planned finger, non-obvious flag, movement and display reasons (`initial`, `position-change`, `non-obvious`, `all`, `manual`). It never infers a shift from interval size and never alters score generation, MIDI grading or timing.
- A shared plan drives the placement banner and VexFlow's supported `Annotation`/`FretHandFinger` modifiers. Advance cues attach to preparation rests and landing fingers to the exact landing notes. After the initial bar the banner references the current position, not an obsolete initial position. Manual Reveal shows all intended fingers for the visible passage plus each hand's next planned movement, even beyond the visible window; details clear at the next bar or when hidden manually.
- The model also permits an explicitly tagged `rested-alternate` fingering for Medium/Hard after a full-beat rest: one adjacent finger, at most two semitones from its normal mapped pitch, no simultaneous shift, with the original expected finger declared. The independent validator rejects unexplained mismatches or alternatives without preparation. The natural-position generator does **not** emit these alternatives; it continues to prefer natural mappings. A validated C4/1 → rest → E4/2 fixture tests actual Smart/VexFlow behavior. This narrow model is not a general substitution/crossing optimizer and needs player review before any routine pedagogical use.
- Fingerprints include generator v2, every difficulty parameter, ranges, mode, tempo, configured assistance mode and whether hints were displayed. All and Smart are assisted from initialization. None stays independent until reveal; assistance already used cannot be cleared by switching to None. A fresh None exercise starts independent practice. Hint switches apply immediately without changing notes/cursor/clock. Historical `reveal` remains parseable for backup compatibility, but active preferences/replay migrate it to Smart; historical fingerprints remain intact.

## Practice interface

- Compact score-first layout, small outcome indicators and a collapsible virtual keyboard. Main controls are Start/Pause, Restart, New exercise and Reveal; Apply & play can apply staged changes and start in one action. Pause remains available while editing a running attempt.
- The compact panel orders difficulty, note-name/octave range, hands/clefs, tempo and assistance. Native note selectors retain MIDI internally and disable endpoints that cannot contain a five-note position or a compatible both-hand pair. Single-position ranges use an explicit explanation; broader ranges explain starting-position variety. Range values stay independent of presets.
- Structural changes wait for **Apply & generate**, New exercise or Apply & play; hint modes, metronome, device/channel and appearance act immediately. Seed, exact movement frequency, interval limits, rhythm/key/meter and timing calibration remain under collapsed Advanced settings. The Apply action remains outside the panel's scrolling region.
- Tablet-sized layouts display two bars at a time (bounded by the selected look-ahead), while desktop can show up to four. Saved settings/comparison fingerprints record the actual displayed bar count. VexFlow bounding boxes extend the SVG viewport for extreme note/finger bounds. The renderer delegates musical annotation placement to VexFlow. See the [QA checklist](QA_CHECKLIST.md) for viewport coverage and device checks.

## Retained platform decisions and limitations

- C/G/F/D major; 3/4 and 4/4; integer-tick eighth/quarter/half/whole notes and rests. Both hands share rhythms and contour; independent polyphony is not implemented.
- Guided/independent modes wait for pitch. Timed mode uses monotonic timestamps and a one-bar count-in; pitch matching is ±450 ms, timing tolerance and input offset are separate. Optional Web Audio clicks never drive scoring.
- Dexie stores local settings and derived outcomes. Sessions save at phrase boundaries and on pause/finish. Reload restores settings/history, not the exact in-progress cursor; seed replay starts over. Long sessions retain note/outcome arrays in memory.
- Session/UI identifiers and exercise seeds use `src/shared/ids.ts`, without Web Crypto dependency. They are not credentials or secrets; any future security-sensitive identifier must require cryptographic randomness with no insecure fallback. HTTP LAN simulator practice works; hardware MIDI requires HTTPS or localhost and explicit permission, without SysEx.
- VexFlow SVG uses embedded Bravura and Academico fonts. Narrow screens permit contained notation scrolling.
- English UI with German core navigation/transport. No thumb-under/finger-over technique, stretches, legato crossings, adaptive scheduler, automatic hint fading, MusicXML, general fingering optimization or hand-size calibration is claimed.
- Passing these hard-rule tests proves consistency with the declared model, **not comfort for every pianist or pedagogical effectiveness**. All new shift sizes, both-hand coordination, high-tempo preparation and musical coherence require manual piano/teacher review. Simulator tests do not prove hardware compatibility.
